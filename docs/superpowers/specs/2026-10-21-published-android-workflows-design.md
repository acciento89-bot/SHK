## First slice: KälteCalc service history
Named appliances and append-only timestamped service visits with explicit before/after readings. Each reading records user-supplied evaporation/suction/condensation/liquid temperatures, suction/discharge gauge pressure, air volume flow, entering/leaving air temperatures. Never infer refrigerant saturation data. Exact existing results: superheat=suction−evaporation; subcooling=condensation−liquid; compressor ratio=(dischargeGauge+1.01325)/(suctionGauge+1.01325); sensible air capacity=airflow×abs(entering−leaving)×0.000335 kW. Preserve negative temperature differences and ratio below1 as diagnostic input, without approval language. Gauge pressures must have positive absolute values; temperatures finite −200..300, airflow0..100000, pressures≤1000. Output exact before/after and after−before deltas, clearly labelled gauge/absolute convention and sensible-only assumption.

`KalteReading` nine fields, `KalteValues`, `KalteVisit(id,assetID,recordedAt,before,after,notes)`, `KalteAsset(id,name)`, `KalteServiceBook(schema=1,revision,assets,visits)`. At most40assets/400visits, unique canonical UUIDs, nonblank named assets≤120, notes≤2000, ISO UTC Instant timestamps, all visit references owned. Saved visits are immutable snapshots; append new visits rather than edit past facts; delete asset only if no visits. `KalteServiceRules.addAsset/addVisit/removeAsset/values/delta/report` return copied books with incremented revision. DE/EN reports derive directly from saved facts, no compliance/repair-success claim.

Separate package-local bounded2MiB UTF8 JSON archive `kalte-service-v1.json`. Strict whole JSON document consumption, exact required schema/fields and duplicate/foreign IDs rejected. Missing creates empty in memory; present malformed/future/oversize never silently reset. Existing current bytes re-read and decoded before every save, including exact idempotent retry. Expected revision inside shared lock prevents stale loss. Flushed same-directory temporary then Files.move(ATOMIC_MOVE,REPLACE_EXISTING), no non-atomic fallback; verify exact bytes before publishing. An injected failure path exercises actual file retention. No previous Android persisted data exists to migrate; don't repurpose Apple archives. UI state publishes only after successful persistence; failure preserves raw editor and previous archive. Explicit same-byte retry accepted, changed stale state rejected.

## Later slices: separate product meaning
- LüftungsCalc: named commissioning projects/rooms and supply or extract terminals with independent target and measured m³/h; separate positive supply/extract room/project totals, absolute/percent deviation (zero target percentage absent), immutable dated adjustment/revisit snapshots, actual commissioning report. Preserve duct/air-change/unit formulas.
- HeizkörperCalc: named retrofit survey rooms with design room heat requirement and current/proposed emitters (manufacturer nominal ΔT50 watts, exponent, count); explicit shared candidate supply/return/room temperatures and existing exact arithmetic/logarithmic/reference selection. Per-room and project capacity/shortfall summaries, at least two operating-temperature scenarios and before/proposed comparison, saved report. No invented radiator/manufacturer database or heat-load certification.
- RohrCalc: named alternative circuits composed of named parallel paths, each containing series segments. Common declared path flow; per segment inside diameter, length, roughness and zeta; preserve exact current water20°C/Reynolds/friction expressions. Sum series losses/volume per path, worst path=max path loss; never sum parallel loss or claim solved balancing/pump selection. Compare baseline/proposal circuits in saved report.
- AnlagenCheck: named installation and immutable repeated visits with existing measurements/user limits, snapshot of versioned custom checklist template and states/notes. Saved history and explicit next-service date in local agenda/share report; no scheduled notification promise until root-approved native permission/timezone acceptance. Never automatic safety release. Template edits create new version; old visits retain exact old template/limits/measurements.

Each later slice requires its own detailed typed contract and actual root RED/GREEN before production. This document does not authorize filling all five with a shared generic worksheet.
